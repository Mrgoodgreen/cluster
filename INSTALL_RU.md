# Инструкция по установке сервиса TLS Classify

## Что это за сервис

**TLS Classify** — сервис автоматической классификации облаков точек LAS/LAZ (наземный лазерный скан, TLS).

Сервис состоит из двух частей:

1. **Management-сервис** (одна машина) — веб-сайт для постановки задач и просмотра статуса.
2. **Worker** (одна или несколько машин с видеокартой NVIDIA) — выполняет классификацию файлов.

Пользователь в браузере указывает папку с исходными LAS на сетевом хранилище (SMB) и папку для результатов. Сервис сам находит все `.las` / `.laz` в папке и обрабатывает их. На одной GPU-машине одновременно обрабатывается **один** файл.

| Параметр | Значение |
|----------|----------|
| Адрес веб-интерфейса | `http://<IP-машины-management>:5357` |
| Порт | **5357** |
| Порт сервиса RAD/CS (TextureEnhancement) | 5257 — **другой**, конфликта нет |

Оба сервиса (RAD/CS и TLS Classify) могут работать на одних серверах одновременно.

## Состав поставки

Вам передаётся папка (архив) со всем необходимым кодом. **Другие папки и репозитории не нужны.**

```
cluster/
├── INSTALL_RU.md          ← эта инструкция
├── CONTENTS.txt           ← список содержимого
├── pipeline/              ← алгоритм классификации (уже внутри пакета)
├── manager/               ← код management-сервиса и веб-интерфейса
├── worker/                ← код GPU-воркера
├── deploy/
│   ├── manager/           ← файлы запуска management
│   └── worker/            ← файлы запуска worker
└── smoke/                 ← необязательная проверка без GPU
```

---

## Что уже должно быть на серверах

Считается, что на серверах **уже выполнена** установка окружения по инструкции RAD/CS, то есть уже есть:

- GNU/Linux
- Docker и Docker Compose
- драйверы NVIDIA (на машинах с GPU)
- NVIDIA Container Toolkit (на машинах с GPU)
- пакет `cifs-utils` (для подключения SMB, как у RAD)

**Повторно устанавливать Docker, драйверы и NVIDIA Container Toolkit не нужно.**

Проверьте перед началом:

```bash
docker --version
docker compose version
```

На GPU-машине дополнительно:

```bash
nvidia-smi
sudo docker run --rm --gpus all nvidia/cuda:12.2.2-base-ubuntu22.04 nvidia-smi
```

Если эти команды работают — можно переходить к установке TLS Classify.

---

## Куда положить поставку

Скопируйте папку `cluster` на серверы, например:

```bash
sudo mkdir -p /opt/tls-classify
# скопируйте содержимое поставки в /opt/tls-classify
# в итоге должен существовать файл:
#   /opt/tls-classify/INSTALL_RU.md
# и папки pipeline, manager, worker, deploy
```

Дальше в примерах используется путь `/opt/tls-classify`. Если вы положили файлы в другое место — подставьте свой путь.

## Шаг 1. Запуск management-сервиса

Выполняется на **одной** машине (той же логике, что management RAD, или на отдельной — не важно). GPU на этой машине не обязателен.

### 1.1. Перейти в папку запуска

```bash
cd /opt/tls-classify/deploy/manager
```

### 1.2. Создать файл настроек

```bash
cp .env.example .env
nano .env
```

### 1.3. Заполнить настройки SMB

Заполните так же, как для RAD (те же хранилища и учётки, если они уже используются):

```bash
MANAGER_PORT=5357

SMB_HOST_1=172.16.16.126
SMB_USER_1=ВАШ_ЛОГИН
SMB_PASSWORD_1=ВАШ_ПАРОЛЬ
SMB_SHARE_FOLDER_1=share

# Путь в веб-интерфейсе = путь внутри контейнера.
# Формат: <IP_хранилища>=/<IP_хранилища>
STORAGE_ROOTS=172.16.16.126=/172.16.16.126
```

Пояснения:

- `SMB_HOST_1` — IP или имя файлового хранилища.
- `SMB_SHARE_FOLDER_1` — имя общей папки (share) на этом хранилище.
- `STORAGE_ROOTS` должен совпадать с `SMB_HOST_1`: слева имя, как его видит пользователь в интерфейсе; справа путь монтирования внутри Docker (`/172.16.16.126`).

Если нужно второе хранилище:

1. Добавьте в `.env` переменные `SMB_HOST_2`, `SMB_USER_2`, `SMB_PASSWORD_2`, `SMB_SHARE_FOLDER_2`.
2. В файле `docker-compose.yml` раскомментируйте строки с `smb2` (есть комментарии в файле).
3. Допишите второе хранилище в `STORAGE_ROOTS` через запятую, например:  
   `172.16.16.126=/172.16.16.126,172.16.16.127=/172.16.16.127`

### 1.4. Запустить

```bash
docker compose up -d --build
```

Первый запуск может занять несколько минут (сборка образа).

### 1.5. Проверить

```bash
docker compose ps
curl -s http://127.0.0.1:5357/api/health
```

В ответе должно быть `"ok": true`.

Откройте в браузере: `http://<IP-этой-машины>:5357`

В разделе создания задачи в дереве путей должен появиться корень хранилища (например `172.16.16.126`).

## Шаг 2. Запуск worker на GPU-машине

Выполняется на **каждой** машине с видеокартой NVIDIA, которая будет считать классификацию.

На одной машине запускается **один** контейнер worker (один LAS в момент времени на эту машину).

### 2.1. Перейти в папку запуска

На GPU-сервере должна лежать **та же** поставка `cluster` (целиком).

```bash
cd /opt/tls-classify/deploy/worker
```

### 2.2. Создать файл настроек

```bash
cp .env.example .env
nano .env
```

### 2.3. Заполнить настройки

```bash
# IP машины, где запущен management TLS Classify, порт 5357
# Не указывайте порт 5257 (это RAD/CS).
MANAGER_URL=http://192.168.0.111:5357

WORKER_ID=gpu-node-01
CARS_TO=7
WORKER_MODE=gpu

# SMB — те же значения, что в deploy/manager/.env
SMB_HOST_1=172.16.16.126
SMB_USER_1=ВАШ_ЛОГИН
SMB_PASSWORD_1=ВАШ_ПАРОЛЬ
SMB_SHARE_FOLDER_1=share
```

Важно:

- `MANAGER_URL` — адрес management TLS Classify на порту **5357**.
- Параметры SMB на worker и на management должны быть **одинаковыми**, иначе пути к файлам не совпадут.

### 2.4. Запустить

```bash
docker compose up -d --build
```

Первая сборка GPU-образа долгая (ставится CUDA/cuML) — это нормально.

### 2.5. Проверить

```bash
docker compose logs -f --tail=80
```

В логе должно появиться сообщение о регистрации worker у management (`registered`).

Повторите шаг 2 на каждой дополнительной GPU-машине, задавая уникальный `WORKER_ID` (например `gpu-node-02`).

## Шаг 3. Как пользоваться (кратко)

1. Открыть `http://<IP-management>:5357`
2. Вкладка **«Создать задачу»**
3. Указать **путь до данных** (папка с LAS на SMB) и **путь до результирующих данных**
4. Нажать **«Создать»** / **«Обработать данные»**
5. Вкладка **«Задачи»** — список, статусы, даты
6. **«Подробнее»** — список файлов, какой worker взял файл, прогресс, лог, кнопка **«Отменить»**

Правила работы очереди:

- файлы (LAS) выдаются воркерам по порядку: сначала все файлы более ранней задачи, затем следующей;
- несколько задач могут быть в статусе processing одновременно — свободные воркеры не простаивают, если у более ранней задачи уже нет свободных файлов;
- если файл результата уже существует — он **не перезаписывается**, обработка этого файла пропускается;
- повторный прогон = создать **новую** задачу;
- если воркер «умер» без heartbeat дольше `WORKER_LEASE_MINUTES` (по умолчанию 30) — его файл снова станет pending.

После обновления кода из Git см. отдельную инструкцию пересборки образов: **REBUILD_PORTAINER.md**.

## Повседневные операции

### Остановка

На машине management:

```bash
cd /opt/tls-classify/deploy/manager
docker compose down
```

На каждой GPU-машине:

```bash
cd /opt/tls-classify/deploy/worker
docker compose down
```

### Запуск после остановки

```bash
cd /opt/tls-classify/deploy/manager
docker compose up -d

cd /opt/tls-classify/deploy/worker
docker compose up -d
```

### Перезапуск

```bash
docker compose restart
```

### Логи

```bash
docker compose logs -f --tail=200
```

### Резервная копия базы задач

База задач хранится в Docker volume management-контейнера (`/data/cluster.db`).

```bash
docker cp tls-classify-manager:/data/cluster.db ./cluster.db.backup
```

Сами LAS-результаты лежат на SMB — их сохраняет ваша обычная процедура бэкапа хранилища.

## Частые проблемы

**Веб не открывается на 5357**  
Проверьте `docker compose ps` и firewall. Убедитесь, что не пытаетесь открыть порт 5257 (RAD).

**В дереве путей пусто**  
Проверьте `SMB_*` и `STORAGE_ROOTS` в `deploy/manager/.env`. Проверьте логи: `docker compose logs manager`.

**Worker не берёт задачи**  
Проверьте `MANAGER_URL` (должен быть `:5357`). С management-машины должен открываться `curl http://<IP>:5357/api/health`. SMB на worker должен совпадать с manager.

**Ошибка GPU / nvidia-smi в контейнере**  
На этой машине должен быть установлен NVIDIA Container Toolkit (как для RAD CS-worker). Команда проверки — в разделе «Что уже должно быть на серверах».

**Конфликт с RAD**  
Не используйте порт 5257 для TLS Classify. Не направляйте worker TLS на API RAD.

---

## Ограничения

- На одно SMB-хранилище в настройках — один share (как у RAD).
- Management и все worker должны видеть одни и те же шары по одним и тем же путям.
- Один контейнер worker на одну GPU-машину.
- Логины в веб-интерфейсе не используются (доступ по сети организации).
